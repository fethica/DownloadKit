# Changelog

All notable changes to this project are documented here.

## Unreleased

### Added
- `DownloadKit` core library (Foundation only, iOS 14+) and optional `DownloadKitUI` library (iOS 15+).
- `DownloadManager`: host-owned, explicit configuration, `start()` before commands, single owner per storage root and session identifier, serialised commands (`enqueue`, `pause`, `resume`, `cancel`, `retry`, `remove`, `setDefaultPolicy`, `setPolicy`), throttled and bounded snapshot stream (`DownloadSnapshotStream`), `localFile(for:)` with read leases, `handleBackgroundEvents(forSession:completionHandler:)`, `flushPendingWork()`, `reconciliationStatus()` (`ReconciliationStatus`, `ReconciliationUnresolvedReason`) and `unreferencedFiles()`, which reports unknown files in `staging/` and `media/` without deleting them.
- Value types: `DownloadID`, `ContentRevision`, `ContentChecksum`, `DownloadRequest`, `DownloadMetadata`, `DownloadState`, `WaitReason`, `DownloadSnapshot`, `DownloadFailure`, `FailureClass`, `TransferFailure`, `DownloadError`, `NetworkPolicy`, `RetryPolicy`, `LocalFileLease`, `LocalFileResult`, `FileStatus`, `TransferSessionEvent`, `SystemTransferTask`.
- Pure state machine with generation counters, idempotent enqueue, conflict detection and bounded retries.
- Persistence specification: `IndexRecord` (public validating initialiser), `IndexContents`, `IndexChangeSet`, `FinalizationJournal`, `RelativePath`, `StorageScope`, `RequestIdentity`, `TaskBinding`; schema version 2 (`IndexSchema.currentVersion`), with refusal of newer versions.
- Dependency protocols: `TransferSessionFactory`, `TransferSession`, `DownloadIndexStore`, `DownloadFileSystem`, `DownloadClock`, `RetryJitter`, `NetworkPathSource`, `URLRefreshing` (`refreshedURL`, persisted, and `transferURL`, resolved for every attempt and never persisted); `SystemClock` and `SystemJitter`.
- `URLSessionTransport`: the production `TransferSessionFactory`, a delegate-based URLSession download adapter with two modes. `Mode.foreground` runs an ephemeral session in the process; `Mode.background` runs a background session under the manager's stable session identifier, with `sessionSendsLaunchEvents`, `isDiscretionary` from `Options.sessionNetworkAccess.scheduling` (user-initiated is non-discretionary), the cellular, expensive and constrained flags from `sessionNetworkAccess`, `waitsForConnectivity` and `Options.resourceTimeout` (`timeoutIntervalForResource`, seven days by default), shared process-wide per identifier. Neither mode keeps a URL cache, cookie store or credential store. In both modes, finished responses are judged and captured into `staging/` inside the delegate callback with a durable receipt; terminal events are stored under `transfer/` before delivery, replayed with their original sequence numbers and deleted on acknowledgement; the backlog marker follows the replay, the task list and every queued callback. Range continuations are validated (200, 206, 416, changed entity tag), resume data is used only when it cannot widen an item's networks, errors and Retry-After are classified, and foreign tasks are left alone.
- `BackgroundTransferEvents(sessionIdentifiers:wakeBudget:)`: the app delegate's receiver for `application(_:handleEventsForBackgroundURLSession:completionHandler:)`, usable before any manager exists. It accepts only the identifiers it was created with. Each accepted handler is called exactly once on the main actor: when the running manager has committed the wake's events up to a wake-drained marker reported after the handler was accepted, or at the handler's own deadline (`wakeBudget`, 20 seconds by default), which the receiver keeps whether or not a manager exists, started or detached. `DownloadManager(configuration:urlRefresher:backgroundEvents:)` takes it.
- The adapter turns `urlSessionDidFinishEvents(forBackgroundURLSession:)` into `backgroundEventsFinished`, in order behind every stored event and never ahead of one waiting to be stored; a marker that arrives while no manager reads is delivered to the next one. The marker's place among the accepted handlers is taken inside that callback.
- Task descriptions name the session (`downloadkit/2/<session tag>/<generation>/<item>`): `TransferSubmission.taskDescription(sessionIdentifier:)`, `TransferTaskReference.init(taskDescription:taskIdentifier:sessionIdentifier:)` and `SystemTransferTask.reference(inSession:)`. The manager reconciles with the session check, so a task naming another session is foreign and untouched. Format 1 descriptions (`TransferSubmission.taskDescription`, `TransferTaskReference.init?(taskDescription:taskIdentifier:)`) are still read.
- A refused continuation (416, or a range answer that cannot be trusted) is recorded under `transfer/<session>/restarts/` inside the callback (best effort) and submitted again from zero by the running manager for the same attempt, through `URLRefreshing.transferURL`, so a signed URL is resolved again rather than reused. After a relaunch the record makes the session ignore the refused task's late completion and route a cancel to its replacement; a record whose tasks are both gone at the next backlog barrier is deleted.
- `SQLiteIndexStore`: the production `DownloadIndexStore` on the system SQLite library, schema version 2 in its own table (a version 1 index is migrated in one transaction), newer schema and foreign or unreadable files refused with the database untouched, one transaction per change set, WAL with full synchronous commits, coalesced progress writes, `opener()`, `flush()` and `close()`.
- `LocalFileSystem`: the production `DownloadFileSystem`, confined to Application Support (or a given base), refusing `..` and symbolic-link escapes, with backup exclusion, file protection on created directories, atomic rename, directory flushes and classified errors (`DownloadFileSystemError`).
- A validating finaliser, used by `DownloadManager(configuration:urlRefresher:)`: response evidence, length, HTML sniffing and the host's SHA-256 in bounded chunks, then flush and atomic rename to `media/item-<generation>[.ext]`; repeatable after an interrupted rename; defers at its deadline, on cancellation and for protected files.
- `DownloadKitUI` (iOS 15+): `DownloadListModel` observes a manager's snapshots while a view is visible, publishes only visible changes, sends commands with in-flight suppression and confirmed removal, and hands out and ends local-file leases. `DownloadControlling` is the protocol it uses; `DownloadManager` conforms.
- SwiftUI controls: `DownloadButton`, `DownloadStatusIndicator`, `DownloadRow`, `DownloadList` (grouped by metadata group), `NetworkPolicyPicker` and `ReconciliationBanner`, with VoiceOver labels, values, hints and custom actions, Dynamic Type and right-to-left layouts.
- `DownloadStrings` and `DownloadStringKey`: English strings in the package, overridable by a `DownloadKitUI.strings` table in the app or by a lookup in the environment. `DiagnosticRedaction` removes URLs and absolute paths from displayed text.
- A sample app (`sample/`, generated with XcodeGen) wiring a background session through a SwiftUI delegate adaptor, with a developer panel, a redacted event log and completed-only local playback through an optional player dependency of the sample.
- A fixture server (`sample/fixture-server`, a separate package) that generates deterministic tones and a large file with recorded SHA-256 values and serves the response scenarios the adapter tests cover.

### Changed
- `BackgroundTransferEvents.init(sessionIdentifiers:)` gains a defaulted `wakeBudget`. Wake handlers no longer wait for a running manager to arm their deadline: each handler's deadline starts when it is accepted and holds when no manager exists, when `start()` fails or is suspended, and after `detach()`. A manager created without a receiver applies `DownloadConfiguration.backgroundWakeBudget` to the handlers given to `handleBackgroundEvents(forSession:completionHandler:)`, counted from that call.
- A wake-drained marker answers only the handlers accepted before the system reported it. A late marker of an earlier wake no longer answers a newer wake's handler; that handler waits for its own marker or its deadline. A `TransferSessionEvent` carrying `backgroundEventsFinished` takes its place when it is created, so a custom session creates it in the system's callback.
- The delegate's refusal of a redirect from HTTPS applies to foreground sessions only, which is where the system asks; background sessions follow redirects automatically and rely on the app's transport security settings. In both modes a finished body whose final URL left HTTPS is now refused as an invalid response and never captured.
- A refused continuation is no longer restarted inside the adapter from a stored submission or the system's copy of the request: the manager submits it again, resolving `transferURL` for it, and submits nothing for an attempt that was removed, stopped, replaced or is waiting for reconciliation.
- `DownloadListModel` (previously a placeholder) takes a controller and publishes presentation `items`; its raw `snapshots` are kept but no longer published.
- `DownloadFileSystem.fileSize(at:)` is replaced by `inspectItem(at:) throws -> FileStatus`, which separates a verified absence from a failed inspection. The port also gains `contentsOfDirectory(at:)`, `readBytes(at:offset:maximumLength:)`, `synchronizeFile(at:)` and `synchronizeDirectory(at:)` (default: does nothing); `DownloadFileSystemError.Kind` gains `directoryFlushFailed`.
- `TransferSession.events` carries `TransferSessionEvent` values: a sequence number and a payload that is a task event, `backlogDelivered`, `backgroundEventsFinished` or `backlogUnavailable`. Sessions must not drop terminal events, must deliver unacknowledged ones again with their sequence numbers after reconnection and relaunch, and must withhold `backlogDelivered` (sending `backlogUnavailable`) while their storage is incomplete. `ReconciliationUnresolvedReason` gains `sessionStorageFailed`.
- `TransferSession.activeTasks()` is replaced by `systemTasks() -> [SystemTransferTask]`, which includes tasks the package cannot map; `acknowledge(through:)` is new; `cancel` returning is the acknowledgement of a stop.
- `DownloadManager.snapshots()` returns `DownloadSnapshotStream`; each iteration is one subscription and ends on `break`, cancellation or release.
- `DownloadManager.detach()` keeps the storage claim while leases are outstanding and returns only after running finalisers returned; a lease, and a running finaliser, keep their manager's claim alive. `LocalFileLease` equality ignores the owner, `endAccess(_:)` ends the lease at the manager that issued it, and ending a lease twice does nothing.
- `IndexRecord` gains `finalizationDestination`, `stoppingBinding`, `stoppedWhileUnconfirmed`, `restartDeferred` and `policyChangeDeferred` (defaulted initialiser parameters; older encodings decode the flags as false). `IndexContents` gains `cleanupPaths` and `IndexChangeSet` gains `cleanupQueued` and `cleanupCompleted`; external stores must persist them and stamp version 2. A version 1 build refuses a version 2 index.
- `FinalizationJournal` drops the unreachable `validated` and `renamed` cases and gains `rejected`; every new attempt resets it to `notStarted`. `ResponseValidators` gains `statusCode` and `mediaType`.
- `SQLiteIndexStore` validates an existing index read-only first, then takes the write lock before it migrates or creates anything and repeats the schema, version and record validation inside that transaction; a newer version or an invalid record committed by another process meanwhile is refused (typed error, rolled back), and the journal mode switches to WAL only after the commit.
- A paused or cancelled attempt that was never confirmed stays fenced, also across a relaunch: `resume` or `retry` creates no replacement until the old task is found, its completion arrives (validated and kept) or its end is proven by the backlog marker or a reported failure; this holds after `reconciliationTimeout` too. A policy change held for an unconfirmed attempt is enforced when its task is found.
- Session events are received outside the serial application of events, and `reconciliationTimeout` records the unresolved status outside it, so both hold while an index write is suspended.
- A 206 continuation must start at the requested offset and carry a confirmed `If-Range` validator; otherwise it restarts from zero. `URLError.dataNotAllowed` is a policy wait and `URLError.noPermissionsToReadFile` a permission storage failure.
- Transfer inbox, capture, resume data and the SQLite database go through one root-confinement rule: a symbolic link in their path is refused.
- A replaced or discarded file stays on disk while a lease on it is outstanding; its deletion intent stays persisted and runs when the lease ends.
- `RetryPolicy.delay(forRetry:jitter:retryAfter:)`: a capped Retry-After can raise the delay but no longer shortens it. Enqueue and source updates reject URLs with a user or password.
- `DownloadConfiguration.init` gains `reconciliationTimeout`, `backgroundWakeBudget` and `finalizationBudget` (defaulted).

### Fixed
- An accepted wake handler is answered at its deadline when the manager's start fails, is suspended in reconciliation or never happens, and after detach.
- A delayed wake-drained marker of an expired wake no longer releases a later wake's handler before that wake's events are committed.
- A refused continuation after its signed transfer URL expired no longer reuses the expired URL.
- A restart record whose process ended before its replacement existed is no longer kept forever.
- Start-up no longer replaces an attempt whose completion was buffered before start, and adopts a task whose binding was never written instead of creating a duplicate.
- A completion arriving after cancel, or replayed with the same file, no longer deletes bytes the record owns; a replayed completion can no longer revive a capture that a recovered validation rejected.
- An inspection failure no longer turns a completed item into `missing`.
- Terminal events, retry firings, bindings and removals whose index write is rejected are kept and retried instead of being lost; failed file deletions are persisted and retried until verified.
- Captured bytes no longer block later attempts after pause, resume, cancel or retry; fresh attempts reset byte counts and validators.
- Pause, cancel and remove keep the stopped task's binding until the cancellation is acknowledged; a pending stop no longer cancels an unrelated or foreign task that reuses the stopped task's number.
- Breaking out of a snapshot loop over a retained stream now unsubscribes.
- A path or policy update during start-up reconciliation no longer creates a replacement attempt over a task that may still exist or a completion that is still buffered.
- A finaliser can no longer leave a media file behind after its item was removed, or write to the storage root after a detach handed it to another manager.
- A lease that outlived its released manager can be ended through the successor, which can then start.
- A finalisation result no longer publishes a completion for an item paused or cancelled while it ran; the validated file stays with the record until `resume` or `retry`.
- A missing backlog marker or an index that keeps rejecting writes no longer blocks reconciliation or a background-wake handler indefinitely.

### Known limits
- Background sessions follow redirects without asking the delegate; there the app's App Transport Security settings are the security contract, and a downgraded body is only refused after the request was made.
- The system treats background transfers started while the app is already in the background (a retry or restart during a wake) as discretionary, whatever `isDiscretionary` says.
- Refusing an index does not mean no file is touched: opening a WAL database read-only may create its `-shm` scratch companion. The database contents are not changed.
- Rolling back to a build that reads only format 1 task descriptions leaves this version's in-flight tasks running as foreign tasks and may submit replacements for the same items; a build before schema version 2 refuses the index. Let in-flight transfers finish, or cancel them, before rolling back.
- Restart records are written best effort; when the write fails, the restart still runs in this process, and a relaunch falls back to the generation fence and reconciliation.
- No production path monitor adapter.
- Not yet verified on an iOS device: background completion and relaunch, force-quit and reboot behaviour, file protection, network flags on real paths, discretionary scheduling and system resume data.
